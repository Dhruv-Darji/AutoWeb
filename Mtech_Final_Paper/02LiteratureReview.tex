\section{Related Work}

\subsection{Multimodal Web Agents}
SeeAct \cite{SeeAct} showed that GPT-4V can work as a general web agent if you feed it both a screenshot and the HTML of a page. The authors note that picking the right element on the page, what they call grounding, is where most of the errors come from. AdaptAgent \cite{FewShotLearning:verma2024adaptagentadaptingmultimodalweb} tried to fix this by giving the model a few human demonstrations so it can adapt to websites it has not seen before. WebExperT \cite{Browsinglikehuman:luo2025browsing} took a different route and added two reasoning modes, one fast and one slow, along with a memory of past attempts. Two recent surveys on (M)LLM based GUI and web agents \cite{tang2025surveymllmbasedguiagents,ning2025surveywebagentsnextgenerationai} keep pointing at the same two problems. The first is that feeding the whole DOM to the model is expensive and wastes tokens. The second is that these agents do not have strong privacy or safety checks inside their action loop.

\subsection{Structural DOM Pruning and Local Grounding}
A normal web page usually has between $10^4$ and $10^5$ DOM tokens \cite{zhang2025prune4web}, which is far more than what most LLMs can take as input. Prune4Web \cite{zhang2025prune4web} handles this by asking the LLM to write a small Python scoring script with keywords and weights, and then a plain Python scorer applies that script to the DOM. This cuts the candidate set by 25 to 50 times and reaches 88.28\% Element Accuracy on Mind2Web when paired with a fine-tuned Qwen2.5VL-3B-Instruct grounder. AutoWebGLM \cite{lai2024autowebglm} keeps the HTML smaller by removing nodes the user cannot click and by capping how deep the tree can go. Agent-E \cite{tarsariya2024agente} squeezes the DOM through the accessibility tree and is the only one in this group that watches the page for changes between steps using MutationObserver. The catch is that it writes those changes back into the prompt as text, so the token count does not actually go down. WebAgent and its HTML-T5 model \cite{gur2024webagent} go the other way and fine-tune an encoder built specifically for long HTML sequences. The thing all four have in common is that each step is treated on its own, with no memory of what was already ranked the step before.

\subsection{DOM State-Change and Semantic Relevance}
D2Snap \cite{schiepanski2025d2snap} brings a DOM down to about $10^3$ tokens by merging nodes from the bottom up, pruning with TextRank, and filtering out unhelpful attributes, but it still works on one snapshot at a time. Agentic Compilation \cite{agenticcompilation2025} cleans up the DOM at each step in a similar one-shot fashion. If you look at the algorithm side, the standard way to compare two trees is Tree Edit Distance \cite{zhangshasha1989ted} and its faster variant RTED \cite{pawlik2011rted}, but neither is plugged into an LLM web agent's filter stage. On the encoder side, Sentence-BERT \cite{reimers2019sbert} showed that you can mix a sparse score and a dense score together, and MiniLM \cite{wang2020minilm} shrinks an encoder down to about 22M parameters that runs in a few milliseconds on a CPU. That kind of speed makes it a real option for ranking DOM elements inside the agent loop. On the grounder side, QLoRA \cite{dettmers2023qlora} makes it possible to fine-tune billion-parameter models in 4 bits on a single consumer GPU, and the Qwen2.5 \cite{qwen25techreport2024} family gives 0.5B and 0.6B open-weight bases that fit comfortably within that setup.

\subsection{Gaps Addressed in This Work}
Three gaps run through the work above. First, sub-1B open-weight grounders show up only as side experiments, with no proper training recipe and no numbers on individual test splits. Second, every DOM reduction method we have looked at runs from scratch on the full page at each step, even when the page has barely moved since the last action. Third, privacy and human-in-the-loop checks tend to be added on after the system is built rather than being part of the action loop itself. The rest of this paper takes these three gaps and works through them one by one.
