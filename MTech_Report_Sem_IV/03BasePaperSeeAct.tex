\chapter{Base Paper: SeeAct}

\section{Overview of SeeAct}
The paper “GPT-4V(ision) is a Generalist Web Agent, if Grounded” introduced an LMM-based (i.e. GPT-4V) GUI automation agent called SeeAct \cite{SeeAct}. SeeAct use Screenshot and DOM both as input to generate an action task \cite{SeeAct}. SeeAct uses LMM to infer the next action from a screenshot while using DOM for element grounding with defined methods \cite{SeeAct}.

\begin{itemize}
    
    \item \textbf{Motivation:} LLM-brained GUI agents solely rely on the DOM, or vision-based GUI agents solely rely on visuals only, while SeeAct provide a simple but promising framework flow with its unique implementation method \cite{SeeAct}.

    \item SeeAct use the Multimodal-Mind2Web dataset, which is a widely adopted dataset for better comparison and evaluation \cite{SeeAct}.

    \item Evaluation is done both on cached pages (offline) and on live websites (online), demonstrating real-world capability of the approach \cite{SeeAct}.
    
\end{itemize}


\section{Dataset (Multimodal-Mind2Web)}
Multimodal-Min2Web is build on top of the Mind2Web dataset, which contains screenshots and HTML values; thus, the author used this dataset for SeeAct \cite{SeeAct} \cite{deng2023mind2webgeneralistagentweb}.
\\
\textbf{Key characteristics of the dataset:}\\
\begin{itemize}
    
    \item Multimodal alignment: In the dataset, each raw (step) contains a screenshot value and corresponding HTML values, making it a multimodal dataset.

    \item Scale \& diversity: Mind2Web (thus Multimodal version) covers over 2,000 tasks drawn from 137 websites spanning 31 top-level domains — ensuring coverage across many real-world use cases and UI styles \cite{deng2023mind2webgeneralistagentweb}.

    \item Dataset splits: Multimodal-Mind2Web provides several splits for evaluation:
    \begin{itemize}
        \item \textit{train:} 7,775 actions from 1,009 tasks
        \item \textit{test\_task:} 1,339 actions from 177 tasks
        \item \textit{test\_website:} 1,019 actions from 142 tasks
        \item \textit{test\_domain:} 4,060 actions from 694 tasks
    \end{itemize}

    \item Each record (action step) contains: screenshot path, raw HTML, cleaned HTML, task, operation info (CLICK/TYPE/SELECT + optional value), candidate DOM elements, metadata like annotation\_id, website, domain, etc \cite{SeeAct} \cite{deng2023mind2webgeneralistagentweb}.

    \item Each record represents a single step, where using grouping of the same annotation\_id we can build an end-to-end task and with shortening of step\_id sequence of steps will also be preserved \cite{SeeAct} \cite{deng2023mind2webgeneralistagentweb}.
\end{itemize}
Multimodal-Mind2Web (13.6 GB) contains a total of 14,273 steps with 2022 tasks, covering 137 websites, spanning 31 top-level domains, with a wide variety of user tasks plus interaction patterns \cite{deng2023mind2webgeneralistagentweb} \cite{SeeAct}.

SeeAct is a pipeline-like, simple framework, with perception, reasoning, grounding and execution like a flow (Fig \ref{SeeAct:Architecral Diagram} shows this flow).

    \subsection{Input preparation (Screenshot + DOM)}
    SeeAct generate input at each step of the task, where it uses Playwright for screenshot and HTML input, but while offline evaluation, it use available data directly from the dataset \cite{SeeAct}. 
    
    \subsection{Action Generation}
        \begin{itemize}
            \item See Act uses LMM (i.e GPT-4V) to generate action description for the next step using screenshot, step history and task \cite{SeeAct}.
            \item SeeAct relies solely on screenshots to generate Action Generation, where it does not use any HTML value while generating next action description \cite{SeeAct}.
            \item The prompting instructs GPT-4V to “imitate humans” browsing the web which identify what page is being seen, reason about what has been done (history), inspect visible webpage details in screenshot (buttons/fields/status), then decide next logical action which may click a button, type into a textbox, select from a dropdown, etc \cite{SeeAct}.
        \end{itemize}
        
    \subsection{Grounding Strategies}
        Action Generation generates an action description, which is not directly able to generate the action or act upon the environment, where the action description is just a text that we have to map to our environment value. 
        \begin{itemize}
            \item SeeAct uses HTML values at this stage to MAP the generated LMM output with HTML values, where it tries to find a relation for action generation.
            \item SeeAct uses DeBERTa model for grounding with a cross-encoder variant, meaning, given a pair of (query, candidate element representation), the model outputs a score representing how likely that candidate is relevant to the query (i.e. the next action) \cite{SeeAct}.
            \item Practically: “query” could be some features derived from the textual intention (e.g. “I want to click the button that says ‘Search’”), candidate element = some DOM element represented by its HTML metadata (tag, text content, attributes). The cross-encoder concatenates both and outputs a relevance score \cite{SeeAct}. 
            \item SeeAct uses this to rank all DOM elements and choose the top-50 for the grounding module (heuristic value). This greatly reduces complexity compared to considering the full DOM \cite{SeeAct}. 
        \end{itemize}
    
        below are the different techniques used as grounding strategies to map action description with the HTML:
        \begin{enumerate}
            \item \textbf{Grounding via Element Attributes:}
            \begin{itemize}
                \item Prompt the model to output detailed attributes for the target element: its type (e.g., BUTTON, TEXTBOX), visible text (e.g., “Submit”, “Search”), and possibly other distinguishing info (position, nearby labels) \cite{SeeAct}.
                \item Then perform a heuristic search over the HTML DOM: find elements whose attributes match the description. If exactly one match: pick it. If multiple: re-prompt model to disambiguate \cite{SeeAct}.
            \end{itemize}

            \item \textbf{Grounding via Image Annotation:}
            \begin{itemize}
                \item For each top-k candidate element, overlay a bounding box and a label on the screenshot image. This is similar to “set-of-mark” prompting used in other VLM/image-grounding works \cite{SeeAct}. 
            \end{itemize}

            \item \textbf{Oracle Action Grounding:}
            \begin{itemize}
                \item human annotators map the model’s textual plan ã to the correct DOM element + operation + value.
                \item This sets an upper bound on what the LMM + planning + reasoning part can achieve, which shows potential if grounding solve perfectly \cite{SeeAct}. Under oracle grounding, SeeAct with GPT-4V obtains much higher performance on online evaluation \cite{SeeAct}.
            \end{itemize}
            
        \end{enumerate}

\section{Results \& Performance}

\textbf{Key Performance metrics used:}
\begin{itemize}
    \item \textbf{Element Accuracy:} fraction of steps where the agent selects the correct DOM element.

    \item \textbf{Operation F1:} token-level F1 score for the predicted operation (click/type/select + value), comparing predicted vs ground truth.

    \item \textbf{Step Success Rate:} considers a step successful only if both the element and operation are correct. Macro-averaged across tasks. 

    \item \textbf{Task Success Rate:} for a multi-step task, the task is successful only if all its steps succeed (strict setting). This measures end-to-end execution correctness (on dataset values). 

    \item \textbf{Online Task Success Rate:} for evaluation on live websites, it measures the proportion of tasks that on agent completes successfully (when grounded via human/oracle). Under oracle grounding, SeeAct achieves 51.1\% success on live websites
\end{itemize}

\section{Strengths of SeeAct \& Its Limitations}
    \subsection{Key Contribution of SeeAct}
        \begin{itemize}
            \item Shows how a vision-based LMM (GPT-4V) can use as an online agent by generating natural-language action plans from visual perception (a screenshot of a webpage) with reasoning and planning, and results in a human-like approach rather than agents that are only DOM-based \cite{SeeAct}.
        
            \item Simple architecture that separates action generation vs grounding vs execution, which provides clarity, flexibility, and ease of extension (e.g. different grounding strategies, different execution backends) \cite{SeeAct}.
        
            \item The Multimodal-Mind2Web dataset was created and released to close a significant gap by providing a realistic, large-scale, multimodal (visual + structural) benchmark for web agents.  This makes it possible to do a thorough investigation and assessment for upcoming generalist web-agent research \cite{SeeAct}.
        
            \item It includes both online and offline evaluation, giving generalization perspective and compatibility option with a simpler LMM architecture as well \cite{SeeAct}.
        
            \item Evaluation of multiple grounding strategies, error analysis (why certain methods fail, which gives actionable insights for future work \cite{SeeAct}.
        \end{itemize}

    \subsection{Limitations of SeeAct}
        \begin{itemize}
            \item \textbf{Grounding:} Grounding remains the major bottleneck. Even the best automatic grounding strategy (Textual Choices) lags far behind oracle grounding. This means many failures arise not from reasoning/planning but from incorrect element selection \cite{SeeAct}.

            \item \textbf{Strict task-success rate:} Strict task-success criterion is bottleneck. Task success requires all steps to be correct, where a single mistake (wrong click, mis-ground) fails the entire task. This makes the metric harsh, and small errors propagate. Also, it reduces the evaluation capability of the fallback loops \cite{SeeAct}.

            \item \textbf{Limited set of supported actions:} SeeAct supports only basic operations: CLICK, TYPE, SELECT. Many real-world tasks involve more complex UI interactions — e.g. hover, drag-and-drop, scroll, keyboard shortcuts, dynamic pop-ups — which are not handled. The paper itself acknowledges that web UI complexity remains a challenge \cite{SeeAct}.
        \end{itemize}
